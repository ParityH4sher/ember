# Threat model and trust boundaries

**Scope:** private health-only scaffold now; handling personal data, credentials and executable tasks later. The host administrator and the operator's deployment configuration are trusted. A browser, local process, imported project, external API response, MCP description or agent may supply untrusted input. A compromised host is outside an in-host container boundary; recovery requires an independent copy of state and keys.

| Crossing / asset | Present control and gap | Required control before expanding access | Evidence to demand |
| --- | --- | --- | --- |
| Browser → Nginx → API; private projects | Loopback frontend by default, no authentication. Peers on the backend network can address the API. Forwarded headers are not identities. | Authenticated principal, ownership check on each operation, TLS on remote transport, CSRF protection for cookie-authenticated writes. Bound body/header sizes and request lifetime. | Other owner cannot read an enumerated ID. Spoofed identity headers are ignored; missing credentials denied before mutation. |
| Operator → provisioning; host administration | Test inventories select hosts for a privileged Ansible play. | For a real deployment, use an operator-owned inventory, key-based access or protected secret injection, and verified SSH host keys. | Verify target selection, install and repeat provisioning on an approved disposable host. |
| Instance → shared service; photos/documents | No adapter implemented. An integration definition is not a grant. | Bind caller, instance, connection, operation and scope; verify destination at connection time, including redirects. Credential per connection with matching upstream scopes. | A and B have different credentials; A cannot see B's resources or cause requests to arbitrary origins. |
| Runner → control plane, filesystem and network | No runner. API Compose limits protect the service, not a future malicious job. | No host socket, home, credentials or shared writer; read-only inputs, bounded output, short-lived audience-bound grant. Default-deny egress including DNS; broker narrow requests, cap CPU/RAM/disk/PIDs and wall time. | Inspect effective runtime policy, prove a sibling's fixture is inaccessible, show resource cleanup and independent observations of denied egress. |
| Model/tool output → authorized action | No model calls or tools today. Persuasive text can look like a system instruction. | Parse bounded structured output as data. Re-check policy on execution. Approval binds exact target, parameter digest, principal, expiry and policy revision; consume once. | Substituted parameters, revoked grant or expired approval fail. A preview cannot start hardware. |
| Backend → lifecycle controller; runtime socket | Ansible operator manages the host outside the API. | Keep service-use identity separate from lifecycle authority. Allowlisted targets, rate limits, durable audit; operator-controlled configuration. | Disconnecting a consumer never stops the service. No host management credentials in backend or agents. |
| Telemetry/backup → operators; sensitive data | Process log and Nginx logs only; no backup or audit subsystem. | Minimize metadata, bound retention, separate audit writer from workers, encrypt off-host backups. Log identity and verdict without credentials, query strings, prompts or upstream payloads. | Verify redaction, access denial, collector-loss signal and clean restore using disposable data. |

### Execution isolation decision

For trusted reviewed adapters, evaluate rootless containers with default seccomp, AppArmor/SELinux where enforced, dropped capabilities, no privilege escalation, a read-only root and bounded scratch. Test effective controls on the selected kernel and runtime. Rootless reduces host privilege; it does not provide a separate kernel. API configuration or a container bridge does not enforce destination policy. Do not colocate unreviewed executable plugins in the core process.

For hostile project code, qualify a disposable microVM or separate execution host. Compare virtualization support, image patching, startup time, memory and tool compatibility on the actual target. If boundary or monitoring tests fail, leave execution disabled; never fall back to host execution. Kubernetes schedules workloads; the chosen runtime, CNI and storage policy still have to enforce isolation. See [sandboxing](../sandboxing/README.md) for the existing filesystem, network and VM evaluations.

Security acceptance applies to the **deployed path**, not just a unit-tested policy function. Authentication at a shared proxy does not prove downstream instance isolation; schema checks, model instructions and human-readable manifests confer no permissions.
