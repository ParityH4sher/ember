## Provisioner and toolchain details

In a disposable copy of the devcontainer environment, `ansible-galaxy collection install -r requirements.yml` selected `community.docker` 5.4.0 and `community.general` 14.0.1. Both inventory syntax checks then parsed but both collections warned they do not support the installed `ansible-core` 2.14.18. Do not confuse module availability with a supported controller or idempotent provisioning.

The examined `community.docker` 5.4.0 implementation (`plugins/module_utils/_compose_v2.py`) passes `--project-directory` set to `project_src`. Thus changing the YAML to `../apps/*` in isolation can **fix the documented CLI command but break Ansible**. Align both paths and verify both effective models. The relevant upstream behavior is documented in the [Compose CLI reference](https://docs.docker.com/reference/cli/docker/compose/).

`go.mod` declares Go 1.24, also used by the Docker builder and devcontainer. The [Go release feed](https://go.dev/dl/?mode=json) returned 1.27.4 and 1.26.11 as current stable series during the review. Treat minimum language version, CI compatibility and a security-supported release builder as separate choices; rebuilding an old toolchain from its tag does not bring it back into upstream support.

## Which document wins?

- The API code is evidence of behavior; OpenAPI is the reviewed public contract. A mismatch is a defect, not a reason to invent an endpoint.
- Use the committed JSON schema for the *current* portable manifest. The YAML sketch in [agent project contract](../agent-project-contract.md) describes richer future work instructions; it is not a valid v1 example.
- [ADR 003](../decisions/003-ai-gateway-shortlist.md) defers gateway adoption. The architecture page's suggested Bifrost experiment is not a selection.
- Keep historical POC scope and wishlist pages. Use the [roadmap](../planning/roadmap.md) for implementation order; use the [operations page](../operations/README.md) for the operator path.
